# Study plan: from builder to junior developer

Started 2026-11-25. 1-2 hours a day, on a phone, from real bugs in my own live projects (see the [study log](README.md)).
Estimates are honest guesses, not promises. Each milestone has a test that proves it, and I don't move on until it passes.

| # | Milestone | Rough time | The test that proves it |
|---|---|---|---|
| 1 | **Read and explain** a small file from one of my projects | 1-3 months | Pick a Drain Check file I haven't seen; explain what each part does, in order, without AI. Claude only checks. |
| 2 | **Fix a small bug myself** | 3-6 months | Claude breaks something small on a copy (a wrong number, a missing check); I find it from the failing test and fix it. Hints only. |
| 3 | **Build a small feature** with its tests | 6-12 months | Add one real feature to Drain Check or Pulse: I write the code and the test, and Claude reviews it like a team lead would. |
| 4 | **Pass a basic coding interview exercise** | 9-18 months | A timed beginner exercise (TypeScript), no AI, explained out loud. |

## Running alongside
- **Investigator case studies** ([cases](../cases/README.md)): write up real traces in my own words. They use what I'm already
  good at, and they're the closest job lane (blockchain investigator or fraud analyst).
- **Bug research**: keep finding and reporting real bugs in public code (no selling). It's the path toward bug bounties.

## How each session runs
1. The story: something that really happened on one of my sites.
2. I predict or answer one question before seeing code.
3. A small bite of code (5-10 lines) with plain-English notes.
4. I explain it back. Claude corrects only what's wrong.
5. Graded honestly. Misses stay in, and redoing them shows up in the "went back and fixed" column.

## Where I am now
Milestone 1, week 1. Lesson 1 = B. Working on: explaining the *how* step by step; knowing which layer a problem is in.
